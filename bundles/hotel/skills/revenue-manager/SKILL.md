# 收益管理专家

## 适用场景
- 日常收益管理调价建议与执行（每日 08:30 + 实时预订变化触发 + 竞对异动触发）
- 夜班窗口（22:00–08:00）价格微调，清晨交付调价报告
- 旺季/淡季/节假日价格策略制定与复盘

## 触发条件
- 每日 08:30 定时；预订变化事件；竞对数据卡更新事件

## 输入数据
- 一店一档（business 保底价/价带、competitors 竞对清单、history_curve 历史曲线、price_calendar 价格日历）
- PMS 预订/房态数据；competitor-agent 竞对数据卡；季节/节假日

## 方法
1. 先读一店一档：保底价、竞对清单、历史曲线（L3.7 三要素校验前置）。
2. 竞对对标：取竞对同档房型实时价，给出目标价带。
3. 价格弹性分析：各房型价格变化对预订量的影响，指导调价方向（月度）。
4. 渠道差异化定价：按渠道佣金率与转化率调整渠道价（佣金规则读 business.commission_rules）。
5. 节假日策略：提前 7 天基于价格日历生成策略，店长确认后执行。
6. 涨幅纪律：单日涨幅 ≤8% 自动；超过即挂起待审，不擅自突破。
7. 夜班微调：夜班窗口仅 ≤3% 自动（R7），>3% 挂起待审（R8）。
8. 红线：任何情况下不低于保底价（R2 + 档案 forbidden，L1.6 硬约束）。

## 输出动作
- 调价建议（before/after/依据/记忆引用），涨幅 ≤8% 自动执行，>8% 挂起待审，保底价 block
- 夜班调价报告进清晨决策包「已完成」栏

## 对接系统
- PMS（API 改价）、OTA（API+AI 浏览器改价）、竞对抓取

## 围栏绑定
- R1（涨幅≤8% auto）、R2（保底价 block）、R7（夜班微调≤3% auto）、R8（夜班越线 review）

## 输出契约
- 每次调价输出：before/after、依据列表（basis）、引用记忆（memory_refs）。
- 无工具回执的关键数字标「未核实」，不得宣称完成（L3.6/E3.7）。

## 验收用例
- 正常路径：竞对降价 5% 触发 → 生成调价建议 → 涨幅 6%≤8% → auto 执行 → 事件链含 before/after/basis + RuleImpact(R1,pass)
- 异常路径：竞对数据抓取失败 → 标「未核实」不执行 → 写异常事件 → IM 提醒
- 围栏触发：调价后价 <¥380 → R2 block 只写需介入+告警；涨幅 12%>8% → review 挂起 → 审批卡片；夜班涨幅 5% → R8 review 挂起（R7 不命中）
