# 超售与价格倒挂看门狗套件

## 适用场景
- 多 OTA 渠道（6–8 个）价格一致性守护；库存同步健康守护；渠道直连稳定性差的单体酒店

## 触发条件
- 周期扫描：价格倒挂每 30 分钟 / 库存一致性每 15 分钟；事件驱动：price.publish 前置校验、order.confirm 前置校验

## 输入数据
- 各 OTA 渠道实时价格与房态（AI 浏览器巡检）、PMS 库存与订单、price_calendar 价格日历、一店一档 business.floor_price

## 方法
1. 倒挂扫描：逐渠道比对同房型同日价格，任一渠道发布价 < 他渠道最低价 90% → 判定倒挂（R17 block），阻断发布并告警；产出倒挂清单（渠道/房型/日期/价差）。
2. 超售防护：order.confirm 前置校验可售数，`available < 0` → R18 block 并立即全渠道下架该房型；同步失败（`sync_failed == true`）→ 自动下架该渠道房态 + 转 review 待人工恢复，杜绝「有房显示无房」的静默漏售。
3. 自动修复：可安全修复项（重新触发同步/回滚到上一致价格）围栏内 auto 执行；涉及对外价格变更一律 review。
4. 修复留痕：每次检出-处置-结果三段式五元事件（channel::parity.alert / inventory.sync / channel::parity.fixed），归因可溯。
5. 价格健康周报：倒挂次数/超售风险次数/同步失败率/修复时长分布，产出渠道健康分，指导渠道直连治理。

## 输出动作
- 倒挂告警与阻断/自动下架/同步重试/价格健康周报/渠道健康分

## 对接系统
- 各 OTA 后台（AI 浏览器）、PMS、channel-reconciler 数据面、IM 班组告警通道

## 围栏绑定
- 检出与下架保护 auto（保护性动作）；R17 倒挂发布 block；R18 超售/同步失败 block；对外价格恢复发布 → review；保底价联动 R2

## 验收用例
- 正常路径：周期扫描全渠道一致 → 无告警 → 周报记录「零异常」
- 异常路径：美团同步失败 → 自动下架美团房态 → review 挂起 → 人工恢复后自动回架 → 全链留痕
- 围栏触发：检测到携程 300 / 美团 268 倒挂 → R17 block 发布 + 告警；available=-1 订单确认 → R18 block + 全渠道下架
