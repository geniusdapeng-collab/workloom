# 获客全链路快照快扫

## 〇、定位

「先体检，再托管」客户旅程的**第一公里**：客户坐在现场，授权 PMS/OTA 与社媒账号后 15–30 分钟拿到《获客全链路快速体检报告》——"原来我的获客链路每年在漏这些钱、漏在这些环节"。这是购买决策的催化剂，也是质检模式（audit_only）的旗舰技能。

复合系统的体检必须**双线**：只看酒店运营，看不见流量从哪漏；只看营销获客，看不见成交在哪断。本技能一遍过两条线，并按「流量→转化→成交」统一排序——先看清漏在哪个环节，再决定托管从哪接管。

与持续体检的分工：
- **本技能（快照快扫）**：基于历史数据快照的存量问题，15–30 分钟一遍过——倒挂/超售漏售/对账差异/存量差评/担保异常 + 账号健康/内容节律/未承接高意向/GEO 缺口/转化组件缺失/线索流失点。
- **持续体检（inspection-suite，1–2 周）**：需要时间才能观察的问题——首响时长实测、差评 SLA 履约率、内容节律趋势、夜班承接效果、能见度周环比。

## 一、何时调用

- 售前演示：客户现场授权 PMS/OTA + 社媒账号后立即触发（目标：当场出报告）。
- 新客户接入质检模式时自动执行一次（基线快照），此后转入持续巡检。
- 客户手动触发"重新体检"（如整改后/旺季前复查对比）。

## 二、输入契约

- 连接器只读快照（平台只读 scope 授权）：
  - **酒店运营侧**：PMS 房态/订单流水（近 90 天，含取消/退款/担保标记）、OTA 价格日历与库存同步日志、OTA 评价（存量未回复差评/评分分布）、渠道账单（最近 1–2 个结算周期）。
  - **获客转化侧**：社媒账号矩阵（账号状态/近 90 天发布节律/播放互动数据）、评论区与私信快照（未回复咨询/高意向信号）、GEO 能见度快照（酒店 query 集提及率/首推率/SOV/引用源）、主页与落地页组件快照（POI/券入口/联系方式/行动锚点）、线索漏斗记录（曝光→互动→询盘→留资→成交）。
- 一店一档（保底价/价格带/佣金率/类目基准参数，缺失时用行业默认值并在报告中标注"按行业基准估算"）。
- 时间预算参数：默认 30 分钟硬上限（超时出部分报告并标注覆盖度）。

## 三、执行步骤（双线静态分析，一遍过）

1. **快照拉取与口径校准**（≤5 分钟）：动作=PMS/OTA/社媒/GEO 连接器只读拉取，归一化为统一数据模型；产出物=快照数据集+覆盖度清单；回执=各源拉取回执（行数/时间窗/完整率）。
2. **酒店运营线·价格健康**：动作=同房型跨渠道价差扫描（倒挂 >10% 告警，对齐 R17 口径）→ 售价 vs 保底价（R2 同源）破防清单 → 促销价异常（低于近 30 天最低价/价保冲突）；产出物=倒挂/破防清单（含每间夜损失估算）；回执=计算过程快照。
3. **酒店运营线·房态与对账**：动作=PMS 房态 vs 各 OTA 可售比对（超售：可售为负；漏售：PMS 有房 OTA 关房/同步失败，对齐 R18 口径）→ 近 90 天超售/漏售事件盘点 → 渠道账单与订单逐笔勾稽（佣金错算/退款未冲抵/券核销差异）→ 担保订单异常归集（R5 同源）；产出物=超售漏售清单+对账渗漏清单+担保异常清单（含估算追回/止损金额）；回执=勾稽差异明细。
4. **酒店运营线·口碑存量**：动作=存量未回复差评（>24h 清单，对齐 R19 SLA 口径）→ 评分分布异常房型 → 差评关键词聚类（对手的差评就是自己的选题，输出给意图雷达）；产出物=口碑风险清单（含差评响应时效与估算流失）；回执=扫描回执。
5. **获客转化线·账号与内容**：动作=账号健康扫描（异常登录/限流信号/防关联风险，G16 同源）→ 内容节律分析（发布频次/时段 vs 流量高峰错配、断更清单）→ 爆款与哑弹归因快照；产出物=账号健康清单+内容节律诊断；回执=计算过程快照。
6. **获客转化线·承接与转化**：动作=评论区/私信未承接高意向盘点（问价/问房态/要联系方式 >2h 未回清单，估算单条线索价值）→ 主页转化组件缺失检查（POI 未认领/券入口缺失/行动锚点缺失/落地页无留资组件）→ GEO 可见度缺口（酒店 query 集提及率/首推率 vs 竞对，引用源缺失清单）→ 线索漏斗断点定位（曝光→互动→询盘→留资→成交五级转化率 vs 行业基准）；产出物=线索流失清单+转化组件缺失清单+GEO 缺口清单；回执=扫描回执。
7. **汇总成报告**：动作=双线结果按「流量→转化→成交」链路排序 → 每条附"环节+问题+证据+建议动作+估算挽回金额" → P0/P1/P2 分级 → 汇总一店一份《获客全链路快速体检报告》+ Top10 行动清单；产出物=报告卡片（IM 触达+工作台可查）；回执=报告事件 ID 与触达回执。

## 四、边界与围栏

- **全程只读**：audit-only patch 生效——酒店侧（调价/退款/排房/回复差评）与营销侧（发布/回评论/私信/投放）一切对外写操作物理 block；本技能只向系统事件库写入发现与报告。
- **估算口径透明**：所有"挽回金额/线索价值"标注计算口径与置信度（精确值/按行业基准估算/经验估计），禁止把估算说成确定值。
- **时间纪律**：30 分钟硬上限；某数据源超时→该检项标注"未覆盖"并降级出部分报告，不阻塞整体。
- 不做什么：不做趋势预测（需观察期数据）、不做首响时长实测（需在线观察）、不做任何处置动作（只出建议）、不碰客资明文（R24 同源，线索盘点只用脱敏聚合数据）。

## 五、与其他技能的协作

- 产出 → `inspection-suite`（持续巡检接管，验证快扫发现并监测时变问题）
- 产出 → `intent-radar`（差评关键词/评论区热问并入意图矿源，反向指挥选题）
- 产出 → `morning-briefing`（体检发现并入晨报"风险"栏直至闭环）
- 报告中的整改项被客户确认后 → 对应域技能生成执行草案（影子模式起）
- 复购/复查场景：与上次报告 diff，产出《整改闭环率》对比卡

## 六、验收用例

- 接入含已知倒挂房型的演示门店，30 分钟内产出报告且该房型出现在价格健康清单（含渠道/价差/建议价）。
- 报告中每条估算金额均带口径标注；任一数据源缺失时报告正常产出且对应检项标注"未覆盖"。
- Top10 清单按「流量→转化→成交」链路排序，每条可定位到具体环节与证据快照。
- 全程事件库无任何平台写操作记录（RuleImpact 全为只读动作）。
